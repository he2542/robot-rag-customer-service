# 生成流程优化：20题同候选验证

**已完成流程提示与输入预检，本地206项测试通过、10项数据库测试跳过。** 20题两版共40份模型输入已冻结；真实生成效果尚无本轮结果。

## 设计依据与修改

《深入理解 AI Agent》v1.2的§1.2.2～1.2.5（PDF27～28，书内19～20页）强调信息充分、验证与约束，以及从简单工作流开始。§2.4.3（PDF55，书内47页）建议按流程组织提示。本次延续单次生成工作流，先完成单轮回答质量，不扩展到会话记忆或Agent工具循环。

面试题参考Q15/362要求分开评估检索和生成，Q251强调固定基线、一次改变一个重要因素，Q264要求对不完整输出检查证据、截断和验收清单。原题定位及完整实现映射见[项目架构](../architecture.md#优化路线与参考映射)。

本次只调整系统提示中的回答流程：

1. 识别问题需要原因、检测、处理、条件或参数，多个需求分别覆盖。
2. 定位适用证据，允许不同来源支持同一问题，不混合不同故障或型号的操作。
3. 检查用户已经完成的操作、排除项及专业边界，必要条件缺失才澄清。
4. 将必要处理步骤写进`claims.text`，引句`quote`负责支持结论。
5. 输出前检查要点遗漏、原文支持和无关建议。

检索、精排、上下文筛选、引用渲染和生成后处理使用相同代码。`RagService`支持内部注入冻结提示版本，因此对照不依赖替换全局常量。

## 冻结协议

| 项目 | 约定 |
|---|---|
| 基线 | 提交3897dd4的第一阶段提示；同一份当前后处理 |
| 样本 | 原300题中每文件4题，共20题；定向回归，不作为独立随机样本 |
| 候选与来源 | 同一批精排前四，经相同条目恢复、审校、去重和预算处理 |
| 历史 | 每题每版独立空历史 |
| 生成 | Qwen-Plus非思考，temperature=0、seed=20261111、max_tokens=1024 |
| 顺序 | 10题基线先、10题优化版先，题目执行顺序固定随机化 |
| 检查 | 同时保留原始JSON与可见回答，分别核对要点、证据、引用和风险 |
| 调用控制 | 预案最多40次尝试，含失败及SDK重试；不调用Embedding、精排或付费评审 |

审读要点在生成前冻结，修正旧标签中把所有附带建议都设为必需项的情况，并保留父题集及修改理由。风险题优先检查停止异常操作、角色边界和原文支持；选购题检查课程范围与具体型号限制。截断保留原始输出并按未完成统计，不删题补抽。
