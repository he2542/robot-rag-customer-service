# 维护周期完整条目测试

维护周期回答使用完整原文，保留部件名称、适用环境、清理与更换周期，减少模型改写时的对象混用和条件遗漏。

## 方法

这是针对项目失败案例提出的工程方案。维护周期类结论中出现明确周期时，程序将引句与本轮来源中的完整编号条目逐一匹配，支持单行条目和多行问答。每组最多 4 个条目，要求全部唯一匹配，随后分别输出原文并执行现有操作风险检查。来源歧义、不完整内容或缺字引句不自动恢复。

测试固定检索结果、模型消息和已有原始生成，仅改变生成后处理。两组回放均通过实际 `RagService` 执行，期间阻断网络。

## 结果

| 检查 | 结果 |
|---|---|
| 定向回归 | 19 项通过，覆盖部件混用、条件交换、否定词、多来源编号、完整问答、歧义及风险过滤 |
| 本地后端测试 | 261 项通过，10 项数据库测试跳过 |
| 40 份输出回放 | 同一维护问题的两版回答改变，其余 38 份不变 |
| 300 份输出回放 | 2 份改变，298 份不变；原有 10 道风险题输出不变 |
| 模型输入、来源与历史检查 | 两组回放全部通过 |
| 模型 API 调用 | 0 次 |

耗材综合问题改为分别展示原文中的部件和适用条件，移除将一种滤网的规定泛化到全部滤网的结论；密封圈的完整问答保留。另一处变化为集尘座滤网回答改用原文格式，清理和更换周期不变。

本次回放验证已有输出的处理行为，未重新评分整体回答准确率。原文中存在不同适用条件和周期描述时仍分别展示，资料冲突、与用户需求的语义相关性及缺失证据需要另行处理。功能由 `RAG_CONTEXT_ENTRIES_ENABLED` 控制，默认关闭。
