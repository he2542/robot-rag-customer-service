# 混合检索设计

本实现以 PostgreSQL 中的同一组有效片段为数据源，将向量召回和中文 BM25 组合。默认两路各取 10 条，等权 RRF 融合后取 4 条供生成使用。

## 两路召回

向量检索对问题调用配置的 Embedding 模型，在当前知识库范围内按余弦距离排序。BM25 使用 `jieba` 搜索分词与 `rank_bm25`：正文和查询统一 Unicode NFKC、大小写及分词规则，保留英文、数字、带点或连字符的编号，去除标点和少量问句停用词。

BM25 只返回实际存在词项交集的片段，不用零匹配候选凑数。小语料中常见词的分数可能非正，因此不单纯按分数正负判断是否匹配。

## RRF

对片段 `d`，融合得分为：

```text
score(d) = Σ 1 / (k + rank_i(d))
```

排名从 1 开始；片段未出现在某路时，该路贡献为 0。默认 `k=60`，两路等权，按数据库 UUID 合并，同一路重复 ID 只计一次；同分按 ID 稳定排序。RRF 避免直接相加不同尺度的 BM25 和向量分数，但不等于模型 rerank，分值不代表置信度。

## 范围与缓存

两路均限定当前文件的 `document_hash` 与 `knowledge_base`，不另读 TXT 重切块，也不混入旧版本或历史上传。数据库返回原始片段与 UUID；公开来源响应不暴露内部 UUID 和分数。

BM25 缓存最多保存一份当前索引。每次查询读取有效片段，比较 UUID/内容快照，变化后重建；锁保护索引替换，查询持有自己的快照。这样也能识别资料文件不变、后台导入刚完成的情况。

每请求读取全量有效文本带来额外数据库和内存开销，目前适合小型知识库。资料规模增长时需另行评估持久稀疏索引、更新策略和资源约束。

## 失败与配置

无关键词匹配时由向量结果参与融合；空白问题不调用 Embedding。召回数据库或嵌入模型故障进入现有错误通道，不静默伪装为低相关性。可选模型精排位于 RRF 之后、最终截取之前，精排故障回退到 RRF；见 [模型精排设计](rerank_design.md)。当前未新增语义拒答阈值或查询改写。

通过 `RAG_RETRIEVAL_MODE` 切换 `hybrid`、`vector`、`keyword`；候选数量与 RRF 参数见 [后端配置](../backend.md)。初始参数并非最优值，调整应参考固定问题集的完整结果。

测试和效果边界见 [测试与评测](../testing.md)、[评测结果](../validation/hybrid-retrieval-20261111.md)。
