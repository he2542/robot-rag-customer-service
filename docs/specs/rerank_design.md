# 模型精排设计

混合检索通过向量与 BM25 召回、UUID 去重和 RRF 得到最多 20 条候选，再由 `qwen3-rerank` 评估问题与正文的相关性，最终保留 4 条。模型精排位于截取上下文之前，不重新切块或写入向量库。

## 接口与身份

`services/rerank.py` 封装 DashScope 原生 HTTP 接口，复用已有 httpx 依赖；`retrieval.py` 仅在 hybrid 模式且开关开启时调用。vector、keyword 和关闭开关时保持原行为。

请求发送问题和候选正文，要求返回全部候选的索引与分数，不要求回传正文。返回索引必须是无重复的完整排列，分数必须是有限的 0—1 数值；按分数排序，同分保持 RRF 顺序。始终映射回本地原始 Document，忽略提供方回传的正文与元数据。来源编号在最终选出片段后生成。

## 配置与失败

默认关闭；配置模型、HTTPS 接口与超时时间后可显式启用。初始 HTTP 读写超时为 3 秒，连接超时不超过 1 秒；这些是网络阶段超时，不是严格的端到端总时限。每次查询只请求一次，不自动重试。超时、网络错误、非成功响应、非法结果和输入预算超出时，回退到 RRF 排名，并记录分类原因，不记录查询、正文、密钥或原始异常。

初版使用保守 UTF-8 字节上界：单个查询/片段不超过 4000 字节，请求的 `查询字节数×片段数＋正文总字节数` 不超过 120000。它不是精确 Token 计数，可能让本可处理的中文长问题跳过精排；不静默截断文本。预算针对 qwen3-rerank，变更模型需核验对应限制。分数只用于本请求内排序，不作置信度或拒答阈值。

## 验证

固定原有题集与参数，对同一批候选比较 RRF 与模型精排的 Hit@4、MRR@4、逐题退化、精排耗时、提供方用量及回退率。回退结果与成功精排分别计数；精排不能恢复未召回的证据。首版 24 题标注不完整且只覆盖 3/5 文件，不能据此判断最终回答准确率或泛化效果。

测试覆盖索引/分数/正文映射、失败回退、开关、模式隔离与最终上下文一致性。数据库测试仍只使用一次性测试库。前端和 HTTP/SSE 契约不变；内部诊断不进入公开来源字段，既有认证与会话授权限制仍适用。
